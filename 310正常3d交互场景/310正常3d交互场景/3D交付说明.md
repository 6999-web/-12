## 3. 当前 3D 架构

当前项目采用“前端建筑层 + GLB 家具层 + Collider 交互层”的方式。

### 3.1 前端建筑层

Three.js 前端负责：

```txt
FloorSystem        地板
WallSystem         墙体
LightSystem        灯光
SelectionSystem    点击选择
SelectionHighlight 选中高亮
FlyKeyboardControls 键盘漫游
ModelEditorPanel   右下角模型编辑器
ObjectInfoCard     信息卡片
```

这些内容都在：

```txt
src/components/scene
src/components/ui
```

### 3.2 GLB 家具层

当前实际加载的模型在：

```txt
public/model/workstation_area.glb
public/model/meeting_area.glb
public/model/hardware_area.glb
```

对应关系：

```txt
workstation_area.glb  80 个工位整体模型
meeting_area.glb      会议桌 + 会议大屏
hardware_area.glb     硬件工位 + 3 台 3D 打印机
```

模型加载逻辑在：

```txt
src/components/scene/ModelAssets.tsx
```

当前不要再把整个实验室烘焙成一个大 GLB。建议继续保持：

```txt
GLB = 家具/设备模型
Three.js = 房间结构、地板、墙体、灯光、交互
Collider = 点击热区
```

如果后续调好位置后想固化到代码，可以把浏览器里调好的 X/Y/Z/旋转/大小同步回：

```txt

```

对应模型的 `defaultTransform`。

## 5. 点击交互机制

当前点击系统原则：

```txt
只点击 collider
不直接 raycast 整个复杂 GLB mesh
```

这样做是为了性能稳定，避免 80 个工位复杂模型导致点击卡顿。

当前逻辑在：

```txt
src/components/scene/SelectionSystem.tsx
src/components/scene/ModelAssets.tsx
```

可点击对象需要满足：

```ts
object.userData.__isCollider === true
object.userData.selectable === true
```

工位 GLB 内部已有 `_collider` 节点，例如：

```txt
seat_r01_c01_collider
seat_r01_c02_collider
...
```

会议区和硬件区如果没有 collider，前端会根据 root 自动生成透明 bbox collider。

## 6. 已知问题：工位点击不能准确绑定到员工

这是当前版本后续必须重点优化的问题。

### 6.1 问题表现

当前点击工位时，可以识别到工位 collider，但还不能稳定做到：

```txt
点击某个具体工位
准确识别该工位对应的员工
显示该员工信息
根据是否有人控制显示/隐藏设备或状态
```

现在信息卡更多是“工位级别”的占位信息，而不是“员工级别”的真实绑定。

### 6.2 当前原因

当前模型和前端之间只建立了：

```txt
seat_rXX_cXX_collider -> 工位编号
```

但还没有建立完整的数据绑定关系：

```txt
工位编号 -> 员工 ID -> 员工姓名 -> 在线状态 -> 项目 -> 设备状态
```

因此后续开发不能只依赖点击模型本身，必须增加一层业务数据映射。

### 6.3 建议后续方案

建议新增一份工位数据表，例如：

```ts
const workstationBindings = {
  "seat_r01_c01": {
    employeeId: "stu_001",
    employeeName: "张三",
    occupied: true,
    project: "AI 视觉识别",
    deviceStatus: "online",
  },
  "seat_r01_c02": {
    employeeId: null,
    employeeName: null,
    occupied: false,
    project: null,
    deviceStatus: "idle",
  },
};
```

点击流程建议改成：

```txt
点击 collider
读取 collider.userData.object_id
得到 seat_rXX_cXX
去 workstationBindings 查询业务数据
如果 occupied = true，显示员工信息
如果 occupied = false，显示空闲工位，或隐藏电脑/设备状态
```

### 6.4 关于“没人时隐藏设备”的建议

如果后续需要实现“没有人的工位隐藏电脑/设备”，不要删除模型，建议使用命名和显示控制。

推荐 Blender / GLB 命名结构：

```txt
seat_r01_c01_root
seat_r01_c01_desk
seat_r01_c01_chair
seat_r01_c01_device
seat_r01_c01_collider
```

前端根据数据控制：

```ts
device.visible = occupied;
```

这样可以做到：

```txt
有人：显示电脑、设备、员工状态
没人：隐藏电脑或弱化显示，只保留桌椅
```

不要在 Blender 里直接删除空工位电脑，否则后续座位状态变化时无法恢复显示。

## 7. 后续开发建议

### 7.1 优先级 1：工位数据绑定

先建立：

```txt
seat_rXX_cXX -> 员工/状态/设备
```

否则点击工位只能显示占位信息。

### 7.2 优先级 2：统一命名规范

建议继续使用：

```txt
seat_r01_c01_root
seat_r01_c01_desk
seat_r01_c01_chair
seat_r01_c01_device
seat_r01_c01_collider
```

其他设备建议：

```txt
meeting_table_root
meeting_screen_root
hardware_workbench_root
printer_3d_01_root
printer_3d_02_root
printer_3d_03_root
```

### 7.3 优先级 3：模型可见性控制

后续可按业务状态控制：

```txt
员工在线 / 离线
工位有人 / 无人
设备在线 / 离线 / 故障
3D 打印机运行 / 空闲
会议室使用中 / 空闲
```

不要再通过删除模型解决状态变化，应通过：

```txt
visible
material opacity
HUD 状态标签
信息卡内容
```

来表达状态。

### 7.4 优先级 4：性能优化

当前已经避免了直接 raycast 大模型，但后续仍需注意：

```txt
不要加载未使用的大 GLB
不要把 node_modules / dist 上传 Git
不要把超过 100MB 的旧模型放进仓库
复杂模型继续用 collider-only 点击
必要时继续用 gltf-transform 优化模型
```
